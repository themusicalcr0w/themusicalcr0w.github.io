Engineering

What makes it work

The project spans input, rules, tools and rendering. These are a few of the decisions behind the footage.

One battle engine

I kept the rules independent of camera, animation and input code. Mouse clicks, VR gestures and opponent decisions become commands to the same engine. It validates turns and targets before changing the match; recorded commands and a fixed random seed let me reproduce it later.

A shared content catalog

The deck builder reads the same creature and card definitions used in battle. Cards combine reusable effects such as power changes, movement and counters. That keeps a new card from needing its own path through the UI and rules, while deck validation catches invalid combinations before a match.

Saves that can recover

Characters are stored as recipes of item IDs and colors. I validate a temporary save before replacing the previous one, retain a backup for recovery and preserve unknown formats. The editor can rebuild the character from its recipe without storing the whole scene.

Keeping the town responsive

My tools group static geometry into spatial batches and reduce distant mesh detail. Collision and interactive objects remain active when render meshes unload. Geometry builds on a worker thread so the loading interface can keep responding.

AI-assisted development

How I use AI to test, fix and profile

I use AI coding agents to investigate bugs, write test scenes and work through fixes. I define the expected behavior and review the result. I give it reproducible scenarios and explicit checks so each proposed fix can be tested.

  1. 01 / Reproduce

    Turn a report into a scene

    The agent helps build small Godot scenes that load real project resources, set up a known state and simulate player actions. Assertions check the outcome; logs and screenshots help inspect failures. Isolated save paths keep the tests away from player data.

  2. 02 / Fix and rerun

    Automate the feedback loop

    I have the agent run the reproduction, inspect the failure, edit the relevant code and rerun focused checks. A Python runner catches script errors, failed assertions and timeouts, including failures that don’t produce a useful exit code. I review the diff and check behavior in the game.

  3. 03 / Measure

    Compare measured runs

    Scripted routes record frame times, CPU/GPU timings and draw calls. I use AI to compare runs and investigate spikes, including the slowest 5% of frames. Controlled rendering tests alternate one feature at a time, with hardware, resolution and warm-up conditions recorded.

Terrain collision regression

Finding gaps in the ground

A terrain check found 4,445 unsupported positions out of 8,550. The fix derives collision bounds from the authored terrain instead of a misplaced fixed origin. The regression test checks those positions and drops the actual player onto a formerly unsupported area to confirm a safe landing.
