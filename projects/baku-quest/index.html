BEHIND THE DEMONSTRATION

Systems built to be checked.

01

Rules separate from presentation

Battle rules run independently of the camera, effects, and input. Commands are validated before they change the state. Seeded randomness and an event log make test scenarios reproducible.

A visual problem and a rules problem can be investigated separately.

02

Saves with a recovery path

A temporary save is written and verified before replacing the primary file. The previous valid version is retained as a backup, while unknown schemas are preserved rather than overwritten.

Validation and a recoverable backup help preserve player choices when a write fails or a saved format is no longer supported.

03

Content through reusable data

Decks, cards, character selections, and presets are validated against catalog data. Shared rules support both player input and the local practice opponent.

New content can use existing behavior instead of duplicating it.

04

Profiling against real movement

Diagnostics exercise walking routes and camera movement. Isolated saves, regression scripts, and recorded results help distinguish a repeatable issue from a one-off observation.

Performance decisions start with a reproducible workload.

Performance work

Optimization work includes baked lighting, occlusion culling, shared texture atlases and mesh batching to reduce rendering overhead. Route-based profiling and regression checks help evaluate the changes.
